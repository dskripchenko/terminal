# Начало работы

## Программа за терминалом

Терминал не запускает программы: он показывает программу, которая работает в
другом месте, и обменивается с ней текстом в обе стороны. В настольном
приложении программа работает в псевдотерминале главного процесса:

```ts
// главный процесс (Electron, Node): node-pty
import { spawn } from 'node-pty'
const pty = spawn(process.env.SHELL ?? 'bash', [], { name: 'xterm-256color', cols: 80, rows: 24, cwd })
pty.onData((data) => window.webContents.send('pty:data', data))
ipcMain.on('pty:input', (_e, data) => pty.write(data))
ipcMain.on('pty:resize', (_e, cols, rows) => pty.resize(cols, rows))
```

```ts
// страница
import { Terminal, TerminalView } from '@dskripchenko/terminal'

const term = new Terminal()
const view = new TerminalView(term, element, { onResize: (c, r) => ipc.send('pty:resize', c, r) })
ipc.on('pty:data', (data) => term.write(data))
term.onData((data) => ipc.send('pty:input', data))
```

На сервере те же два потока идут через WebSocket. Задайте программе `TERM`
равным `xterm-256color`: это то семейство, на языке которого говорит терминал.

## `Terminal`

```ts
new Terminal({ cols?: 80, rows?: 24, scrollback?: 1000, foreground?: '#000000', background?: '#ffffff' })
```

`foreground` и `background` сообщаются программе, когда она спрашивает цвета
(OSC 10/11: так делает `vim`, чтобы выбрать светлую или тёмную схему).

| | |
|---|---|
| `write(data)` | что написала программа — любым куском, последовательность может разойтись на два |
| `onData(fn)` | что уходит программе: клавиши, набранные в представлении, вставки, ответы на её вопросы |
| `input(data)` | отправить программе самому (кнопка, которая набирает `ls`) |
| `paste(text)` | отправить текст как вставку: в метках bracketed paste, если программа их просила |
| `resize(cols, rows)` | новый размер; строки основного экрана переразбиваются под новую ширину, курсор остаётся на своём символе |
| `reset()` | вернуться в исходное состояние |
| `onTitle(fn)`, `title` | заголовок, заданный программой (OSC 0/2) |
| `onCwd(fn)`, `cwd` | рабочая папка, о которой сообщила оболочка (OSC 7) |
| `onBell(fn)` | BEL |
| `onMark(fn)` | интеграция с оболочкой (OSC 133): `A` — начало приглашения, `B`/`C` — команда, `D` — она завершилась; со строкой |
| `onChange(fn)` | что-то на экране изменилось |
| `screenText()`, `lineText(i)` | экран или строка буфера текстом |
| `buffer` | активный экран: `lines` (прокрутка назад и экран), `x`, `y`, `base` (первая строка экрана среди `lines`) |
| `normal`, `alt` | два экрана; `buffer === alt`, пока работает полноэкранная программа |
| `trimmed` | сколько строк уже отброшено сверху прокрутки: на столько сдвигаются абсолютные номера строк |

Режимы, заданные программой, тоже можно прочитать: `applicationCursor`,
`bracketedPaste`, `mouseTracking`, `cursorVisible`, `cursorStyle`,
`reverseVideo` и другие.

Строка (`Line`) даёт для каждой клетки `char(x)`, `width(x)` (0 — правая
половина широкого символа), `fg(x)`, `bg(x)` (0 — цвет по умолчанию,
`PALETTE | n`, `RGB | 0xrrggbb`) и `flags(x)` (`BOLD`, `ITALIC`,
`UNDERLINE`…; номер ссылки — с 16-го бита, её адрес в `terminal.links`), а
также `text()`; `wrapped` означает, что строка продолжается на следующей.

## `TerminalView`

```ts
new TerminalView(term, host, {
  fontFamily?, fontSize?: 13, lineHeight?: 1.25,
  theme?: LIGHT_THEME,
  altIsMeta?,            // Alt отправляет ESC перед клавишей; на Mac по умолчанию выключено (Option набирает символы)
  onLink?: (url) => {},  // ссылка, нажатая с Cmd (Ctrl)
  onResize?: (cols, rows) => {},
})
```

Представление заполняет `host`; его размер задаёт число колонок и строк, а
изменения размера отслеживаются (`fit()` делает то же вручную). На странице
только видимые строки: прокрутка назад прокручивается как обычно, и новый
вывод не сдвигает вид, если он не в самом низу.

| | |
|---|---|
| `focus()` | клавиатура — терминалу |
| `getSelection()`, `hasSelection()`, `selectAll()`, `clearSelection()` | выделение (перенесённые строки склеиваются) |
| `scrollToBottom()` | к самому свежему выводу |
| `setTheme(theme)` | цвета: `foreground`, `background`, `cursor`, `selection` и 16 цветов `ansi` |
| `dispose()` | элемент и обработчики представления удаляются (терминал остаётся) |

**Клавиши.** Текст идёт через скрытое поле ввода, поэтому работают раскладки и
методы ввода; стрелки, Home/End, Page Up/Down, Insert/Delete и F1–F12
отправляются так, как их отправляет xterm, с модификаторами (`ESC [1;5C` для
Ctrl+→); Ctrl с буквой — управляющий символ по месту клавиши (Ctrl+C — это ^C
в любой раскладке); Alt отправляет ESC перед клавишей, когда включён
`altIsMeta`. Cmd+C / Cmd+A на Mac, Ctrl+Shift+C / Ctrl+Shift+A в остальных
системах копируют и выделяют всё; вставка — средствами браузера.

**Мышь.** Протягивание выделяет; двойной щелчок выделяет слово, тройной —
строку; Shift расширяет выделение. Когда программа просит мышь (`htop`, `mc`,
`vim` с `mouse=a`), щелчки, протягивание и колесо принадлежат ей — с Shift
они остаются терминалу. В полноэкранной программе без отслеживания мыши
колесо отправляет стрелки.

**Цвета** — пользовательские свойства CSS на элементе представления:
`--dsk-term-fg`, `--dsk-term-bg`, `--dsk-term-cursor`, `--dsk-term-selection`,
`--dsk-term-0` … `--dsk-term-15`. Готовы `LIGHT_THEME` и `DARK_THEME`.

## Интеграция с оболочкой

Оболочка, которая размечает свои команды — OSC 133 (`A` — приглашение, `B` —
набранная команда, `C` — она выполняется, `D;код` — она завершилась), то же из
633 VS Code и `633;E;текст` для того, что запущено, — читается: `term.commands`
перечисляет команды (строки, код выхода, текст, время начала и конца),
`term.onCommand` сообщает о каждом изменении. Представление ставит метку у
приглашения каждой команды — выполняется, завершилась, с ошибкой; при
наведении — команда, код выхода и длительность; щелчок по метке выделяет вывод
команды, — а `view.scrollToCommand(-1 | 1)` поднимает к верху предыдущее или
следующее приглашение. Скрипты, которые заставляют zsh, bash или PowerShell
размечать команды, — забота хоста.

## Ссылки, поиск, очистка

```ts
new TerminalView(term, host, {
  onLink: (url) => openInBrowser(url),
  links: [{ pattern: /[\w./-]+\.\w+:\d+/g, activate: (text) => openAtLine(text) }],
})
```

Веб-адреса и гиперссылки OSC 8 уходят в `onLink`; каждый из `links` находит в
тексте свой вид ссылок (путь со строкой, номер задачи) и открывает его по Cmd
(Ctrl) и щелчку. `view.find(pattern)` отмечает все совпадения в прокрутке назад
и на экране и возвращает их число; `view.showMatch(i)` делает одно текущим и
прокручивает к нему; `view.clearFind()`. `view.clear()` очищает прокрутку назад и
экран, оставляя строку приглашения наверху.

## Не поддерживается

Картинки в терминале (sixel, iTerm2, графика Kitty), протокол клавиатуры
Kitty, строки двойной ширины и высоты (DECDWL, DECDHL), режим 132 колонок,
текст справа налево, запись в буфер обмена из вывода (OSC 52 — отказ
намеренный). Строки DCS (`tmux` passthrough, `DECRQSS`) читаются и
отбрасываются.
